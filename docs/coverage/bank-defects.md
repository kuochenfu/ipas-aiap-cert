# 題庫與學習筆記的已知缺陷

撰寫詳解與選項解析的過程中發現、但**不屬於當次任務範圍**的問題。集中記錄於此，避免只留在一次性的工作紀錄裡而流失。

每筆都經過獨立覆核（實作者提出、審查者查證來源），但**尚未經人工事實查核**。

## 答案鍵僅在特定讀法下成立的題目

這類題目不是詳解寫錯，而是題目本身有瑕疵。處理原則是**把成立的讀法明寫進詳解**，而不是假裝沒有歧義。

## 解析管線殘留（2026-08-17 已修正）

中級三科的 **110 題**學習指引參考題，詳解曾同時壞在四個地方——2026-08-14 只記錄了前兩項，
2026-08-17 重寫時才發現後兩項：

| 症狀 | 範圍 |
|---|---|
| 詳解開頭黏著正解選項原文＋沒切掉的「解析：」標記 | 110 題全部 |
| 句子被截斷 | `senior-ai-tech-guide-q004`（「…（B）屬於生成式任務如風格轉換，」） |

| **答案區塊錯位**：詳解講的是另一題的內容 | `senior-ml-guide-q032`（問隨機擾動，詳解在講匿名化再識別風險） |

另有 `_No extractable text on this page._` 這種轉檔標記混入詳解結尾。

**處理方式**：不修 parser 重跑，而是比照初級的作法，以**手寫詳解**覆蓋這 110 題
（寫在 `src/data/explanations/senior-*.ts`，經 `resolvePastExamExplanations` 依 id 合併）。
理由是這批殘留有四種不同成因，且原始文字本身品質也不足；重寫同時解決殘留與內容兩件事。
`tests/parseResidue.test.ts` 現在禁止任何詳解殘留與章節前言混入。

**連帶效果**：改寫時採「逐項點名 A/B/C/D」的句型後，`render.ts` 的選項解析後備抽取器
接得住這些詳解，中級三科的「通用填充句」比例從 **59% 降到 5%**（1,446 個欄位中僅餘 71 個）。
抽取器同時擴充為認得三種寫法（子句開頭字母、括號寫法、連接詞串接），並支援
「一個子句同時解釋兩個選項」時兩者共用該段——這也讓 114-2 與 `gen-*` 兩批一併受益。

### `studyNotes.ts` 的「補充」段落與題庫循環（不是錯誤，是證據力的限制）

`junior-genai` 的核心名詞——LoRA、MCP、Chunking、知識蒸餾、同態加密、SynthID、AgentKit、情境感知代理、Graph Prompting、Encoder-Decoder、思維鏈——**全部**落在標示「補充 A／A2／A3｜題庫考點反推（非官方講義）」的段落；只有 TCO、邊緣運算、資料漂移在正文有涵蓋。那些卡片有**逐字抄答案鍵**的情形（`:2246` 對 AgentKit 的定義即 `115-1 q21` 選項 D 的原文；`:2201` 直接寫「115-1 Q06…正解為…」）。

因此：**用這些卡片去佐證這些題目的詳解，是循環論證**——一致只證明內部不矛盾，不構成正確性證據。撰寫或複審 `junior-genai` 的 115-1／115-2／114-4 內容時務必注意。

**但這條限制不適用於 guide 批次**（見 `docs/coverage/explanations-overhaul.md`）：`studyNotes.ts` 的 3.1（1468-1700）、3.2（1788-2037）、3.3（2300-2569）是**正文**，約 753 行正文對 445 行補充，而 `junior-genai` 的 29 題 guide 全部落在正文涵蓋範圍內。
