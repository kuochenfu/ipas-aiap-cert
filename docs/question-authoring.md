# 出題方針（新題庫命製指引）

本站的**新題庫**（`src/data/practice/`，七科各 100 題）不是真題，是自行命製的。這份文件記錄
命題規格、資料形狀、產出流程，以及**四個型別檢查抓不到、只能靠流程與測試擋住的坑**。
下次要為新科目生成題庫時，照這份走。

真題與其詳解不適用本文件——那條路徑是 `docs/markdown` → `npm run parse:papers` →
`explanations/*.ts`，規則見 `CLAUDE.md`。

---

## 1. 為什麼要有方針：LLM 命題的預設失敗模式

不給約束時，LLM 寫出來的題目會穩定地壞在同幾個地方。這些都是實測結果，不是假想：

| 失敗模式 | 實測數字 | 後果 |
|---|---|---|
| 正解字母偏向 A | senior-ai-tech **A:69 / B:27 / C:4 / D:0**；aiot-junior-basics **A:86** | 「不會就選 A」有七成命中率，鑑別度歸零 |
| 題幹與正解關鍵字重疊 | 題幹寫「即時」、正解寫「即時處理」 | 不懂概念也能靠字面配對答對 |
| 錯誤選項明顯不同類 | 三個技術名詞配一個管理名詞 | 一眼刪去，變成三選一甚至二選一 |
| 全是定義題 | 未約束時 Direct Concept 佔比可過半 | 只測背誦，測不出應用與判斷 |
| 每題只落在單一節點 | 跨節點題近乎為零 | 練完仍不會處理真實情境的複合問題 |

方針的每一條規則都對應上表的一列。**規則不是形式主義，是在補這些洞。**

## 2. 命題規格

### 2.1 節點與題數

題目依**評鑑內容節點**平均分配，配額定義在 `src/domain/assessmentTopics.ts` 的
`practiceTopics`。餘數平攤到前幾個節點，不要集中。

現行配額（各科 100 題）：

- AI 應用規劃師五科：依各科節點數平攤（例：`junior-ai-basics` 9 節點）
- AIoT 考科一：9 節點 → 11×8 ＋ 12
- AIoT 考科二：6 節點 → 17×4 ＋ 16×2

`topic` 欄位必須寫成 `<節點碼> <節點名稱>`（例 `A1.1 AI 基礎概念`、`L23303 模型訓練、評估與驗證`），
與 `assessmentTopics.ts` 完全一致——多一個空格或少一個字，題目就會被歸為「未分類」。

### 2.2 認知層級（`meta.cognitiveLevel`）

| 層級 | 意義 | 佔比 |
|---|---|---|
| L1 | 記憶：定義、名詞、配對 | 10–15% |
| L2 | 理解：比較、分辨界線、判斷敘述正誤 | 25–30% |
| L3 | 應用：把原則套到具體情境、計算 | 35–40% |
| L4 | 分析／評估：多重限制下的取捨、根因推論 | 20–25% |

重心在 L3–L4（合計約六成）。**分布是硬約束**，寫完要量測並回頭調整（見 §4.3）。

### 2.3 難度（`difficulty`）

易 25%／中 50%／難 25%（測試放行區間為 20–30 / 45–55 / 20–30）。

難度與認知層級**不是同一件事**：L1 的題目也可以很難（冷門名詞），L4 的題目也可以不難
（限制條件明顯）。兩者各自獨立標註。

### 2.4 題型原型（`meta.archetype`）

| 原型 | 在測什麼 |
|---|---|
| `Direct Concept` | 定義與名詞（**上限 15%**） |
| `Concept Boundary` | 兩個相鄰概念的分界線 |
| `Comparison` | 兩種方案的取捨 |
| `Scenario Selection` | 給定情境選最適方案 |
| `Best Engineering Decision` | 多重限制下的最佳工程決策 |
| `Constraint Change` | 條件改變後答案跟著換 |
| `Troubleshooting` | 由症狀推根因 |
| `Architecture` | 分層職責與元件配置 |
| `Incorrect Statement` | 四個敘述中挑出錯的那個 |

### 2.5 跨節點（`meta.crossNode`）

**至少 20%** 的題目要同時牽涉另一個節點，並在 `meta.crossNode` 標明。真實問題不會照著
大綱的章節切開，只練單節點的人到了現場仍然接不上。

### 2.6 判斷分界（`meta.decisionBoundary`）— 每題必填

一句話說明：**條件變成什麼樣時，這題的答案就會換人。**

> 若故障紀錄累積到每種型態數百筆且標註一致，監督式分類會反過來優於異常偵測，
> 因為它能直接指出「是哪一種故障」而不只是「不正常」。

這是這批題目最有價值的部分——只背答案的人拿不到它。它會渲染在揭曉區
（`renderDecisionBoundary`，虛線框）；**只寫不顯示等於沒寫**。

### 2.7 選項設計

- 四個選項**屬於同一概念類別**（都是演算法、或都是架構決策、或都是處置動作），
  不要三個技術名詞配一個管理名詞。
- 長度與句式相近。正解特別長或特別具體是最好認的破綻。
- **題幹與正解不得有關鍵字重疊**。題幹說「即時」，正解就不要寫「即時處理」——
  改寫成「在毫秒等級內完成判斷」。
- 每個錯誤選項都要**錯得有道理**：它應該是某種真實的誤解，而不是隨便湊的。
  在 `meta.distractorTypes` 標明是哪一種：

  | 干擾類型 | 意義 |
  |---|---|
  | `Correct in Different Context` | 換個情境就是對的 |
  | `Neighbor Concept` | 相鄰但不同的概念 |
  | `Terminology Swap` | 兩個名詞的定義被對調 |
  | `Layer Confusion` | 答到了別的層（拿網路層的措施回答裝置層的問題） |
  | `Overgeneralization` | 把「有幫助」誇大成「必定」「即可免除其他」 |
  | `Partial Truth` | 部分正確但不完整，或算式用錯了分母 |
  | `Wrong Trade-off` | 取捨方向反了 |

- **每個錯誤選項都要有一條解析**（`choiceExplanations`），說明它錯在哪、
  而不是只說「不正確」。正解不寫在這裡（正解的說明在 `explanation`）。

### 2.8 情境（`sourceRef`）

AI 應用規劃師五科限官方學習指引的五大產業：金融／醫療／工廠／教育／農業。
AIoT 兩科的評鑑內容另涵蓋家庭／交通／能源，故其清單是五大產業的**超集**。

分成兩份而不是直接放寬同一份，是為了不讓 AIoT 的額外場域鬆掉五科既有的約束
（`tests/practiceBank.test.ts`）。

## 3. 資料形狀

```ts
{
  id: "<subjectId>-practice-q001",     // 三位數字、從 001 連號
  subjectId: "aiot-junior-iot",
  prompt: "...",
  choices: [{ id: "A", text: "..." }, /* B, C, D */],
  answer: "B",
  explanation: "...",                   // 為什麼正解成立
  choiceExplanations: { A: "...", C: "...", D: "..." },  // 恰三條，不含正解
  topic: "B1.1 系統元件與架構",
  difficulty: "難",
  source: "generated",
  sourceRef: "工廠",
  meta: {                               // 目前只有 AIoT 兩科帶 meta
    cognitiveLevel: "L3",
    archetype: "Scenario Selection",
    concepts: ["邊緣運算", "延遲預算"],
    constraints: ["latency", "safety"], // Scenario Selection／Constraint Change 必填
    distractorTypes: { A: "Layer Confusion", C: "Wrong Trade-off", D: "Partial Truth" },
    crossNode: "A3.2",                  // 選填，全科需 ≥20%
    decisionBoundary: "若延遲要求放寬到⋯",
  },
}
```

型別在 `src/data/types.ts`（`Question`、`QuestionMeta`）。**七科的新題庫現在都帶 `meta`**
（AIoT 兩科在命題時就依規格寫入，AI 應用規劃師五科於 2026-08-22 補標）。

**補標與原生命製不同，這個差別必須誠實記錄。** 五科的題目是在沒有題型約束的情況下先寫好的，
事後補標只能如實反映它們在測什麼——實測偏重記憶與理解（L1 16–31%、L3 23–45%、
Direct Concept 17–33%），達不到 §2.2 的區間。因此 `tests/questionBankMeta.test.ts` 把契約分成兩層：
結構檢查適用七科，分布區間只適用 AIoT 兩科，五科改以**基線快照**守住不再退步。

**要讓五科的分布往上走，只有兩條路：改寫題目，或加題稀釋。** 調整標籤不算——
把明顯的 L1 標成 L3 只會讓這份後設資料失去意義。

2026-08-22 採用的是**加題稀釋**：既有 500 題一題不動，另補 215 題 L3／L4 情境題。

### 加題稀釋的成本怎麼算

既有題目不移除時，超標的類別只能靠把分母做大來壓低比例：

$$\text{所需總題數} \ge \frac{\text{該類別的既有題數}}{\text{目標比例上限}}$$

以 senior-bigdata 為例：33 題純記憶要壓到 20% 以下，總數就得達到 165 題，因此至少要加 65 題。
**成本由「最超標的那一類」決定，而不是由「還缺多少 L4」決定**——這一點與直覺相反，
實際算之前很容易低估。各科的瓶頸也不同：

| 科目 | 卡住的是 | 需要的總題數 | 實際加題 |
|---|---|---|---|
| junior-ai-basics | L1 上限 | 135 | +45 |
| junior-genai | 跨節點下限 | 113 | +20 |
| senior-ai-tech | L1／純記憶上限 | 140 | +42 |
| senior-bigdata | 純記憶上限 | 165 | +66 |
| senior-ml | L2 上限 | 140 | +42 |

（實際加題數略高於最低值，是為了在區間內留一點餘裕。）

### 為什麼五科的區間比 AIoT 寬

要讓五科完全對齊 AIoT 的規格，總共需再多寫約 **160 題**（合計 375 題），
而其中多數只是為了把記憶題佔比從 19% 再壓到 15%。

**真正讓使用者有感的是 L4 從 1% 拉到 15–27%、跨節點從 0% 拉到 15–24%**；
多幾題定義題不會讓人變得不會判斷。因此五科採用較寬的區間（方案 C），
把資源集中在能改變練習體驗的那兩項上。

## 4. 產出流程

### 4.1 寫題（逐節點）

一次寫一個節點的份量（15–20 題），寫完立刻 `npx tsc --noEmit`。不要一次寫 100 題
再回頭修——格式錯誤會散在各處，找起來比重寫還久。

### 4.2 先確認節點名稱

**寫之前先 `grep` 一次 `assessmentTopics.ts`**，把節點碼與名稱抄下來。

> 實際發生過：憑印象把 B2.2 寫成「物聯網軟體與韌體開發」，實際是「雲端環境數據收集與平台設計」。
> 16 題整組報廢重寫。型別檢查完全不會抓——`topic` 就是個字串。

### 4.3 量測分布並回頭調整

寫完全部後統計認知層級、難度、原型、跨節點比例。第一版幾乎必定偏離區間
（考科二初版是 L1 7%、L4 28%、難 21%）。

調整時**只動真正落在灰色地帶的題目**：一題到底算 L3 還是 L4 本來就有判斷空間，
把邊界題往需要的方向靠是誠實的；把明顯的 L4 硬標成 L1 只是為了湊比例，那是造假。

### 4.4 重新配置正解字母

```bash
npx tsx scripts/rebalance-answers.ts src/data/practice/<subject>.ts            # dry-run
npx tsx scripts/rebalance-answers.ts src/data/practice/<subject>.ts --write
```

這支腳本交換「正解選項」與「目標字母選項」的文字（題目語意不變），並同步搬移
`choiceExplanations` 的鍵、`meta.distractorTypes` 的鍵，以及詳解裡指名字母的句型。

**只在新題庫首次寫完時跑一次**，跑完提交。它每次都產生新配置、不是冪等的，
不要放進 CI，也不要對既有題庫重跑。

### 4.5 驗收

```bash
npm run build && npm run test
```

## 5. 四個型別檢查抓不到的坑

這四個都真的發生過，而且**都不會讓建置或型別檢查失敗**。現在每一個都有測試擋著。

### 坑 1：換位時 `meta.distractorTypes` 沒跟著搬

`choiceExplanations` 改了、`distractorTypes` 沒改 → 畫面上「干擾類型」標到別的選項。
兩者都是 `Record<string, string>`，型別完全合法。

**擋法**：`tests/questionBankMeta.test.ts` 斷言兩者的鍵相等，且恰為三個錯誤選項。

### 坑 2：詳解裡指名的選項字母

「若把選項 C 改成⋯」這類句型，指的一律是**正解**（那是「何者不正確」型題目的標準說明）。
換位後沒同步改字母，就會指向另一個選項，讀者被直接誤導。

實際發生 **8 次**，其中 **3 次在早先已經「驗過」的題庫裡**——因為當時只檢查了鍵的一致性，
沒有檢查散文裡的字母。

**擋法**：`tests/questionBankMeta.test.ts` 掃 `explanation`、`decisionBoundary` 與所有
`choiceExplanations`，凡出現「選項 X」就斷言 X 等於該題的 `answer`。

> 推論：**寫詳解時盡量不要指名字母。** 用「把它改成⋯」而不是「把選項 C 改成⋯」，
> 這類缺陷就從源頭消失。指名字母只在「何者不正確」型題目真的需要時才用。

### 坑 3：同長度的節點共用同一條答案序列

九個 11 題的節點若都套同一條序列，餘數會固定偏向同幾個字母。
實測讓 `aiot-junior-basics` 的 D 只剩 **19 題**，其餘三個字母各 27。

**擋法**：序列**逐節點**生成（`scripts/rebalance-answers.ts` 已是如此），
且 `tests/questionBankMeta.test.ts` 斷言每個字母 20–30 題。

### 坑 4：序列太「整齊」

第一次做字母平衡時直接輪替 A、B、C、D，結果每四題恰好是一個 ABCD 排列——
比原本的 A 偏斜更好猜。

**擋法**：`tests/practiceBank.test.ts` 的兩項檢查（週期分組不得全同字母、
連續四題恰為 ABCD 排列的區塊比例 ≤50%），序列在生成時就先過這兩關。

## 6. 測試守住哪些事

| 測試 | 守住 |
|---|---|
| `tests/practiceBank.test.ts` | 形狀契約（四選項、恰三條選項解析、節點合法且不超額）、`sourceRef` 情境清單、答案序列的週期與區塊檢查 |
| `tests/questionBankMeta.test.ts` | 節點配額精確相符、認知層級與難度分布區間、Direct Concept ≤15%、跨節點 ≥20%、干擾類型鍵一致、判斷分界非空、字母各 20–30 題、詳解指名字母須指向正解 |
| `tests/assessmentTopics.test.ts` | 節點碼格式（兩套編碼體系）與不重複 |

**這些測試只驗形狀，驗不了內容對錯。** 分布達標的題庫仍然可能整題寫錯。

## 7. 內容正確性：測試管不到的部分

現行七科的新題庫**全部是 LLM 命製、未經人工事實查核**。風險依序：

1. **AIoT 考科二**（100 題）— 沒有官方學習指引也沒有公告真題，依 115 年度簡章的
   評鑑內容大綱加一般工程知識命製。B2.3 的 OEE／稼動率／投資回收期算式若官方定義不同，
   答案會直接錯。
2. **中級三科**（各 100 題）— 未經初級那批的八輪內容複審。
3. **AIoT 考科一**（100 題）— 有官方學習指引可對照，但仍未逐題查核。
4. **初級兩科**（各 100 題）— 經過八輪 LLM 內容複審，仍無人工查核。

新增題庫時，**把待複審狀態一併記進 `docs/backlog.md`**。已知的個別瑕疵記在
`docs/coverage/bank-defects.md`。
