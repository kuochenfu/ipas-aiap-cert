## 流程

`brainstorming（釐清 4 個關鍵決策）→ 寫 spec → 逐題盤點 → 缺口歸群 → WebSearch/WebFetch 查證 → 撰寫 → build + test`。使用者在腦力激盪階段一次拍板四件事（落地形式、範圍、是否聯網查證、盤點嚴謹度），之後全程無需再確認，這是本次流程順的主因。

未走 subagent-driven：本次為單檔序列寫入（同 2026-06-18 那次的瓶頸），且盤點需要把兩科講義與題庫同時放在同一個上下文裡比對，拆開反而會失去判斷依據。

## 學到的事（給未來）

1. **「覆蓋率」要先定義才能盤點。** 一開始想用二元的「有／沒有」，實作到第 20 題就發現大量灰色地帶——講義提了名詞但沒寫辨析（如「L1 和 L2 正則化」只有一行）。加入 ⚠️「部分覆蓋」後判定才穩定，而且⚠️ 這一類其實是最有價值的補充目標：學習者以為讀過了，考場上卻答不出來。

2. **先把資料壓成適合閱讀的形狀，再讀。** 直接讀 `studyNotes.ts`（9,288 行 JSON-in-TS）與題庫 JSON 極耗上下文。改用兩支一次性腳本把講義攤平成大綱、把題目壓成「題號｜題幹｜正解」的精簡行，兩科各降到約 28k 字元，才有辦法在同一個上下文裡完成比對。**盤點類任務的第一步應該是「做一份適合比對的中間表示」，而不是硬讀原檔。**

3. **概念卡的「題庫怎麼考」欄位是複審的著力點。** 每張卡都標了題號，複審者可以直接對答案驗證，不必回頭讀講義。這比純敘述式的補充教材更容易稽核——這個設計值得沿用到中級三科。

4. **JSON-in-TS 的陣列尾端插入必踩逗號。** 七處插入有五處因為前一個元素結尾沒有逗號而 `TS1005`。教訓：對這種大型字面量做尾端追加時，先確認前一元素是否已有分隔逗號，或直接以腳本統一補。

5. **時效性查證有「查了才知道自己過期」的價值。** 原本只打算補技術現況，實際查證後發現《人工智慧基本法》已經完成立法、EU AI Act 高風險時程已被延後——這兩件事都會改變學習者對現有題目的理解。**凡是題目涉及法規時程的，一律查，不要憑既有知識寫。**

6. **搜尋結果的可信度要分級。** 法規與官方機構（全國法規資料庫、moda、AIEC、EU 官方公報）可直接引用；模型版本號與市場份額類的來源多為內容農場，因此補充 B 刻意避開具體型號，只寫「模型分層與其適用場景」這種不會過期的結構性敘述。第一次猜的 `pcode=J0140004` 抓到的是《中小企業輔導體系建立及輔導辦法》——**猜 URL 一定要驗內容，HTTP 200 不代表對**。
