# 專案回顧（Retrospective）— 2026-08-14：初級兩科詳解與選項解析全面改寫

把初級兩科 **435 題**的詳解與**逐項選項解析**全部改成手寫的一次改寫。

- 分支：`explanations-overhaul`（11 個任務、38 個 commit，已併入 `main`）
- 規模：369 真題 ＋ 66 `gen-*` 補充題 = **435 題**，**1,305 條選項解析**
- 測試：約 140 → **219**
- 覆蓋文件：`docs/coverage/explanations-overhaul.md`；題目瑕疵：`docs/coverage/bank-defects.md`

## 起因

使用者回報「有些題目說明得並不好」。量測後發現兩個結構性問題，都不是個別題目寫得差：

**選項解析大多根本不存在。** 它不是手寫的，而是拿選項文字去比對一份 106 條詞彙表自動組出來。這只在選項是單純名詞時有效；真題多為情境題、選項是整句敘述，比對不到就什麼都不顯示。實測：全部 435 題裡只有 **29 題**（25 ＋ 4）有完整三條，**1,135 / 1,305 個欄位**顯示同一句通用填充。

**115-2 兩科各 50 題的詳解是樣板產生的**——用題目文字重排出一段話，零資訊量。

## 做了什麼

刪掉整套自動組句機制（`glossary.ts`、`choiceAnalysis.ts`、`buildFallbackExplanation`、`buildChoiceExplanations`），資料層改為 `{ explanation, choices }`，然後依考卷切成九批逐題手寫，最後補上 `gen-*` 的 198 條。

每批走：派工 → 實作 → 獨立審查 → 修正輪 → 範圍複審。

## 最重要的一課：一個缺陷類別的四層剝離

整個計畫的價值，有一半在於這件事被逐層挖出來。順序如下：

**第一層——發現缺陷集中在「收尾句」。** 許多詳解以一句「其餘三項都是…」把三個干擾項壓成一句話。Task 6 的審查發現：該批**所有**判準與事實錯誤都在那一句裡，沒有一個出現在逐項的選項解析中。

**第二層——關鍵詞找不到句型。** 實作者用「其餘三項」去搜，找到 5 則；改用語意枚舉，找到 **16 則**。下一批實作者數 14 則、審查員數 24 則。最後一批：標記詞 12 則、語意 28 則。**用關鍵詞找一個句型，找到的是用了那個詞的句子，不是那個句型。**

**第三層——收尾句只是症狀，判準句才是病灶。** Task 8 有一則「修好」了：收尾句被刪掉，但**產生那個收尾句的判準句一字未動**，而三條反駁早就悄悄改用另一條正確的規則在論證。審查員的診斷成為後續的標準檢查：

> 抽出詳解裡陳述「排序／選擇規則」的那一句，套到三個干擾項上，並確認三條反駁是依據**同一條**規則。詳解的規則與反駁的規則不一致時，失效的是詳解那一條。
>
> 另外要檢查：這條規則會不會把某個干擾項分到**正解那一側**。

最後一項檢查抓到三個缺陷，而它原本不在任何清單裡。典型案例：收尾句說干擾項都「中間沒有一個可以推翻它的環節」，而同一則詳解替正解辯護時用的正是「必須經律師逐項覆核才會生效」——**同一個性質，同時出現在兩邊**。

**第四層——收緊判準會製造新的失敗。** Task 9 的 q015 修了三輪。第二輪把判準對 A 收緊之後，D 露出來了——因為在原本寬鬆的寫法下，C 和 D 都是靠「負面語氣 vs 正面效果」這種模糊讀法**碰巧**通過的。所以完整規則是：

> **判準每收緊一次，就要重新對每一個干擾項檢查一次。** 收緊本身會讓原本靠模糊矇混的項目暴露出來。

實作者自己的結論最精準：「我第二輪只檢查了剛修好的 A 是否成立，從未把收緊後的判準重跑 C 和 D。」

## 其他教訓

### 「憑感覺判斷哪些該留」不可靠，而且錯得很徹底

四批有既有詳解的任務，實作者的初判保留率是 40/50、0/50、0/50、0/40。**Task 4 初判「值得保留」的 40 則，最後有 33 則被重寫。** 全計畫 369 則真題詳解，最終只有 57 則與改寫前逐字相同。

那 40 則之所以躲過初判，不是因為文字有何不同，而是**它們讀起來很通順**。後續批次因此一律改成「先對全批跑複述檢查，不准先分類再抽查」。

### 揭露不等於修正

有兩次實作者在報告裡誠實標註「這是本批最勉強的一格」，然後沒有修它。誠實揭露值得肯定，但**報告裡寫了不代表問題解決了**。控制端要把自陳的弱點當成待辦，不是當成已處理。

### 測試可能完全不咬

Task 3 的審查對測試做了突變測試：把樣板句注入選項解析、甚至把整條換成一個字元 `"x"`，測試照樣通過——因為長度與樣板句檢查只套在詳解上，選項解析只驗「非空」。

**每批產出 200 條字串，測試只認證其中 50 條**，而漏掉的那 150 條正是這整個計畫存在的理由。

守衛補在第三批，不是最後——**留到最後才補的守衛，一條都攔不到**。後續每次加測試都要求做突變驗證。

### 「我改了什麼」的證明方式，會隨任務性質失效

第一批用 `grep -v` 檢查刪除行來證明「詳解未動」，成立是因為當時唯一合法的刪除只有一個固定字串。但對**會重寫字串**的批次，這個檢查完全失明。

後續一律改成：**解析兩個 commit 的模組、逐欄位深度比對**。這也是唯一擋得住「編輯發生在同一個物件字面量內部」的方法（`gen-*` 那批就是這種情況）。

### 一致性檢查可能是循環論證

派工要求「不得與 `studyNotes.ts` 衝突」。但 Task 6 的實作者主動指出：`junior-genai` 的核心名詞幾乎全落在標示「題庫考點反推（非官方講義）」的補充段落，那些卡片是 LLM 從**這個題庫本身**反推出來的，有幾則還逐字抄了答案鍵。

**與它們一致是預期結果，不構成正確性證據。** 這種主動指出「我這項驗證其實沒有證據力」的判斷，比多找到幾個錯誤更有價值。

而三批之後，Task 9 的實作者用行號範圍**反駁了這條前提**——那個科目有 753 行是真正的正文，guide 批全部落在裡面。審查員逐一核對後裁定它是對的。**過度概化的警告也會被文件固化，所以最終文件寫的是收窄後的正確版本。**

### 捏造來自「想把弱干擾項講得體面」

全計畫每一處捏造——虛構題幹目的、調整名詞定義、加一句沒依據的實務補述、附加一個絕對化的後果——都源自同一個衝動：讓一個很弱的干擾項聽起來站得住。

**單選題只需要相對排序。** 承認干擾項不完美、改跟另一個選項比，比硬拗安全。這條後來成為明文規則，且「承認式寫法」在每一批審查都被判為正確處理。

配套的自檢：**句子出現「因而…／進而…」時，要驗證那一步真的成立。** 最後一批 198 條裡，這類詞出現 **0 次**。

### 修一處，要 grep 整則

Task 7 有一個誇大在詳解裡修好了，**同一個誇大仍活在該題的選項解析裡**——因為那個欄位不在修正輪的 diff 範圍內。同類事件在 Task 10 也發生一次。

### 實作者傾向低估自己的依據

**三批**出現同一件事：實作者標註「這項只靠我自己的知識、沒有來源」，審查員查證後發現有經典文獻、成文法理或本國法源支撐。低估比高估更麻煩——它會讓人工複審把力氣花在錯的地方。

### 控制端也會出錯，而錯誤要當場更正

計畫原本不含 `gen-*` 那 66 題，因為我告訴使用者「它們本來就自帶選項解析」。那是錯的——`grep -c "choiceExplanations"` 在那些檔案裡回傳 **0**。我把 115-2 由樣板產生的東西誤認成手寫內容了。

發現後直接向使用者揭露、由使用者裁定納入範圍，成為 Task 10。**沒有把錯誤留在原地。**

### 分組提交，不要押到最後

一次派工在寫入前死於 API 過載，損失近兩小時推理、磁碟上零產出。後續派工一律要求「每約 10–15 題提交一次」。

### 「不要製造填充」比「填滿版面」重要

最後補上考試檢討頁的選項解析時，最終審查指出：這會讓 `senior-ml` 的 150 個錯誤選項欄位有 **145 個（97%）**顯示同一句通用填充——而這條分支刪掉舊機制的理由，正是「讓『沒有詳解』看起來像『有詳解』」。

改成以「這題有沒有手寫解析」為閘門：初級 435 題全部顯示，中級 332 題**整個區塊不顯示**。**寧可留白，也不要假裝有內容。**

## 這次的機制設計，哪些真的有效

- **每批獨立審查、審查員自己重跑而不看實作者的清單。** Task 8 的再審自行從全 50 則抽出判準句重驗，包含實作者宣稱「已乾淨」的 36 則——這比「檢查它說它改過的地方」強得多，因為前兩輪的失敗正是「上一輪宣稱乾淨的部分其實不乾淨」。
- **規則逐批累積並寫進派工。** 最後一批的派工帶著十一條規則，每一條都是前面某一批花一輪審查換來的。最後一批的內容品質明顯最高（判準句 27/28 乾淨、通用化近乎零、絕對語誇大 0 次）。
- **把「不屬於本次範圍」的發現寫進版控。** `docs/coverage/bank-defects.md` 在施工中建立。審查員後來指出：那些發現原本只存在於 gitignored 的工作區報告，收尾時會全部流失。
- **擴大掃描而不是只驗證單點。** 實作者發現三則詳解被截斷，審查員把同樣的檢查跑遍五科——找到中級三科**全部 110 題**都有同類殘留。同理，發現一則貼上錯誤後，用 6-gram Jaccard 掃過 752 則詳解確認它是孤例，兩分鐘給出「不是系統性問題」的確定答案。
- **最終審查獨立重跑量測。** 它把刪掉的舊機制還原、逐格重放，文件裡每個承重數字都重現；並抓到兩處文件錯誤（保留數 50 應為 57、後備路徑的描述會導致未來有人誤刪）。
