- 規模：新增 **150 題**真題（中級三科各 90 → **140 題**）＋ **150 則詳解** ＋ **42 題圖片轉錄**

- 修好 **3 個**解析器缺陷（皆為靜默損壞，不會讓解析失敗）

## 起因

使用者要求把三份 PDF 轉成 markdown「for coming tasks」。轉檔本身十分鐘結束，但驗證題號完整性時發現：科二第 49 題四個選項全空、科三第 46/47 題選項只剩「描述 A、描述 C、描述 F」而描述 A~F 的定義不知去向。

追下去發現這不是新問題。`senior-ml-114-2-q45` 從專案初期就以「原始 PDF 選項為圖片，pdftotext 無法擷取」的形式記在 `CLAUDE.md`、`AGENTS.md` 與 `docs/coverage/bank-defects.md` 三個地方，被歸類為**已知限制**——也就是「知道了，但不打算解決」。

它其實是**壞題**：一道四個選項都空白的題目，放在站上不叫限制，叫故障。

## 最重要的一課：「圖片」這個詞把問題分到了錯的類別

使用者問「圖片的部份有建議的方式嗎？」。這句話的自然讀法是一個**資產管線問題**：怎麼把圖抽出來、放哪裡、怎麼渲染、要不要進版控、授權如何。我一開始也是往這個方向想的——`pdfimages -list` 跑下去，看到每頁的 rgb 影像，準備評估抽圖與裁切。

轉折點是一個很笨的動作：**把 PDF 頁面 render 成 PNG，然後真的看一眼。**

看到的東西讓整個解空間翻轉——那些「圖」是**程式碼的截圖**。CIFAR-10 的 Keras 程式碼、`train_test_split` 的四種寫法、console 的 classification report、交易紀錄的表格。內容全部是文字，只是被印成了像素。

一旦看清這件事，原本的比較（要不要抽圖、放 `public/` 還是 base64、怎麼處理浮水印）全部作廢，因為文字轉錄在每個維度上都贏：

- **不是替代品，是還原。** 轉錄不損失任何資訊，還多了可搜尋、可複製。
- **浮水印。** 每頁都疊了 iPAS 的粉紅／青色浮水印，正好壓在程式碼區塊上。裁頁面會連浮水印一起帶走。
- **手機。** 1084px 寬的程式碼截圖在手機上等於不能讀。
- **repo 維持純文字**，不用開資產管線、不增 bundle。

**教訓**：使用者用某個詞描述問題時，那個詞帶著一套隱含的解法分類。在照著那個分類去比較方案之前，先確認問題真的屬於那一類——具體到這次，就是「先把圖打開來看」。這個動作花了兩分鐘，省掉的是一整套不需要存在的圖片管線。

真正的圖表只有 4 張（訓練曲線、ROC 四曲線、分佈圖、損失曲線），佔 42 題裡的 4 題。**先看，再分類，最後才比較方案。**

## 第二課：補上缺失資訊之後，才驗得出既有內容的錯

`senior-ml-114-2-q50` 的舊詳解是這樣寫的：

> 依附圖（訓練/驗證損失曲線）的繪圖慣例，空格 1 應填 `"r-"`、空格 2 應填 `"r--"`（C、D 正確），官方答案為 C。（⋯因附圖缺失，依官方答案，中信心）

補上圖之後才看得到：圖例是 **Training Loss 藍色實線、Validation Loss 紅色虛線**。成立的是敘述 A（`"b-"`）與 D（`"r--"`），不是 C 與 D。

答案字母 C 是對的。**理由整條是反的。**

這個缺陷有兩個性質值得記住：

**一、它在只有答案可校驗時完全隱形。** 舊詳解是從官方答案字母反推理由——答案對了，所以自檢通過；但站上顯示給使用者的是**詳解**，不是字母。使用者讀到的是一段錯誤的顏色對應。

**二、它自己標了「低信心」，然後就留在那裡。** 這正是 2026-08-14 那次回顧已經寫過的一課：「揭露不等於修正——報告裡寫了不代表問題解決了」。這次是同一個模式的另一種形態：**標記在資料裡的自陳弱點，同樣不等於待辦**，它需要有人把它變成待辦。

**推論**：所有標了「因附圖缺失／依官方答案／低信心」的中級詳解，都應視為**未經驗證**而非「已知較弱」。這次補圖已順帶重寫了 42 題中相關的部分，但 `docs/coverage/bank-defects.md` 裡其餘標了低信心的條目仍待同樣處理。

## 第三課：我用正則去檢查「句型」，量到的是正則的表達力

寫完 150 則詳解後，我想驗證「每則都逐項點名 A/B/C/D，而不是只講正解」。第一個版本是一條精心設計的正則：字母後面接「說／稱／把／主張／指⋯」等一長串動詞。

結果：**40 則不合格**。

看了幾筆才發現全是誤判。例如 `senior-bigdata-115-1-q38` 被判成一個字母都沒點名，但它明明寫著「⋯故 B 不正確，即為答案。A 正確描述 K 匿名⋯；C 正確描述亂數回應⋯；D 正確指出⋯」——只是「A 正確描述」的「正」不在我那串動詞裡。

我量到的是我的正則涵蓋了多少種中文句法，不是內容合不合格。

換成一個弱得多但**健全**的檢查——四個字母是否各自以獨立 token 出現過（前後非英數）——結果 0 則不合格，而且這個結果可信。

這與 2026-08-14 那次的「用關鍵詞找一個句型，找到的是用了那個詞的句子」是同一課的變體。差別在於這次是**檢查端**而非搜尋端，失敗方向也相反（那次是漏報，這次是誤報）。統一的說法是：

> **正則能表達的是字面，不是語意性質。** 拿它做內容檢查時，要選一個「就算通過也不代表對、但沒通過一定有問題」的弱條件，而不是試圖精確編碼那個性質。

## 第四課：解析器的缺陷是靜默的，而且只在新資料上現形

三個缺陷，全部由這份新考卷觸發，全部**不會讓解析失敗**：

| 缺陷 | 症狀 |
|---|---|
| 科三後段頁面的欄位標題順序相反（「題目 答案」而非「答案 題目」） | 標題被當成內文，黏進題幹 |
| 「二、程式題」區塊標題未列為雜訊 | 黏進**前一題**最後一個選項的尾巴 |
| 共用引文被 pdftotext 斷成兩行（「⋯請回答」／「第 42~43 題。」） | 觸發詞比對不到，整段下一組題目的前言被併進前一題的選項 |

現有的警告機制只有兩條：「解析出 N 題（預期 50）」與「有空白選項」。三個缺陷一條都沒觸發，因為它們產生的是**看起來合理的輸出**——選項有文字、題數正確，只是文字多了一截。

發現它們靠的是把 150 題全部印出來人眼掃過。這不可規模化。

**可行的守衛**：這三種損壞都讓欄位**變長**。一個「選項文字長度超過同題其他選項數倍」或「選項尾端出現題號模式 `\d+\.`」的健檢，成本極低且能攔下整個類別。這一項尚未實作，已列入下方待辦。

另外，`git diff` 在這裡發揮了關鍵作用：每修一個缺陷就重跑解析並 diff `past-exams/*.json`，確認**只有預期的那幾行改變**。三次修正的 diff 分別只動到 1、2、1 個欄位，證明修正沒有波及舊卷。

## 其他觀察

### 給使用者做範圍決策的數字，自己要先驗證過

我問使用者「只補 4 題還是全部 38 題」時，38 這個數字來自一條偵測「下圖／附圖／程式碼如下⋯」的正則。使用者選了「全部 38 題」之後，我擴大偵測條件重掃，得到 44 個候選，實際有圖的是 42 題——其中 `senior-bigdata-114-2-q48`（題幹是「根據上述結果，下列何者正確？」而結果在圖裡）根本沒被第一版偵測到，而它是最嚴重的壞題之一。

使用者是拿 38 這個數字在做決策的。所幸「全部」這個選項在語意上涵蓋了實際範圍，但如果他選的是「只補 4 題」，那 4 題也是同一條不可靠的正則挑出來的。

**教訓**：選項裡的數字是決策依據，不是說明文字。在丟出 AskUserQuestion 之前，那個數字要用比「一條正則」更紮實的方法確認過，或者明確標成估計值。

### 寫死題數的測試，擋住的是擴充而非回歸

`tests/data.test.ts` 原本寫 `expect(past.length).toBe(50 + expectedGuideCounts[sid])`。加進第二個梯次的那一刻它就紅了，而它紅的原因不是任何東西壞掉。

改成先斷言「每個梯次各 50 題」、再斷言總數 = 50 × 梯次數 + guide 數。這樣才真的釘住了不變式（每份公告試題 50 題），而且下次加考卷時只需要在 `sittings` 陣列加一個字串。

**判準**：一條測試在功能正常擴充時會不會紅？會的話，它釘的是快照不是不變式。

### 三來源設計扛住了這次擴充

`past-exams/*.json`（機器產物）／`explanations/*.ts`（手寫）／`generated/*.ts`（手寫新題）的分層，讓「圖片轉錄該放哪」這個問題有唯一答案：手寫層。轉錄因此天然免疫於 `npm run parse:papers` 的覆寫。

新增的 `tests/figures.test.ts` 把這件事釘死（`past-exams/*.json` 不得含 `figures`／`choiceFigures`），因為這個錯誤犯下去之後，症狀要到下次重跑解析才會出現，且表現為「轉錄無聲消失」。
