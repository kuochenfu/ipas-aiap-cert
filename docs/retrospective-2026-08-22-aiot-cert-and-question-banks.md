# 專案回顧（Retrospective）— 2026-08-22：AIoT 證照上架與 640 題新題庫

從兩份 PDF 開始，站上多了一張證照、兩個科目、一整套學習主題工具，以及 640 題新題目。

- 新增 **640 題**：AIoT 官方練習 80、考科二自編 60、七科新題庫中的 500（中級三科 300 ＋ AIoT 兩科 200）
- 題庫總量 **1,117 → 1,757 題**
- 測試 **268 → 422**（20 → 24 個測試檔）
- 新增 **15 個** AIoT 節點的備考筆記、**120 條**縮寫速查
- 學習主題頁的六項工具從 AIoT 推廣到全部七科

---

## 起因

使用者丟來兩份 PDF（AIoT 初級考科一學習指引 156 頁、115 年度簡章 25 頁），要求轉成 markdown。
接著是一句話定調了整個後續：

> 「先把 80 題練習評量解析成題庫，網頁上與 AI 應用規劃師的初級、中級區分，不要混在一起。」

「不要混在一起」是這次架構決策的全部依據。既有的資料模型只有「級別 → 科目」兩層，
`getSubjectsByLevel(level)` 是唯一入口。新證照塞不進去。

---

## 最重要的一課：把新維度加進去之前，先問「舊維度是哪一層」

第一個念頭是把 AIoT 兩科當成新的 `level`（`"aiot-junior"`）。這樣改動最小——
`Subject.level` 是字串，加兩筆就完事，一行 UI 都不用動。

沒有這樣做，是因為使用者的原話是「兩張證照」，而 level 這條路會讓
「AI 應用規劃師的初級」與「AIoT 的初級」在同一個下拉選單裡並排。那正是「混在一起」。

於是加了 `cert` 維度，導覽變成 `home → cert → level → mode`。**AIoT 目前只有初級**，
所以 level 那一層在 AIoT 底下只有一個選項、點下去像是多餘的一步。當下這確實是多餘的，
但使用者選了保留：「讓未來有中級的空間」。

真正的收穫不在這個決定本身，而在它逼出來的一個問題：**既有的 `level` 到底是什麼？**
翻出來的答案是——它一直同時扮演兩個角色：「難度階段」與「這批科目屬於誰」。
只有一張證照時這兩件事重合，看不出來。加第二張證照才把它們拆開。

**教訓**：要加一個新維度時，先確認舊維度沒有偷偷兼職。如果有，新維度該做的不是
「擠進舊維度」，而是**把兼職的那部分接管走**。

## 第二課：解析器的方言選項，預設值就是回歸測試

考科一的 80 題練習評量要走解析管線，但它的格式與既有五科不同：半形選項標記
`(A)` 而非全形、每個選項各有一段解析、分節結構。

作法是給 `parseStudyGuide` 加四個**選用**欄位（`choiceMarker`、`perChoiceExplanations`、
`source`、`sections`），全部收在 `paper-manifest.ts` 那一筆裡。

關鍵是驗證方式：**省略這些欄位時，行為必須與既有五科完全相同**。這句話可以直接執行——

```bash
npm run parse:papers && git diff --exit-code src/data/past-exams/
```

重跑解析、五科的 JSON 一個位元組都沒變。這比任何單元測試都硬。

**教訓**：擴充純函式解析器時，「舊輸入產生舊輸出」是可以逐位元組驗證的。
只要產物已經進版控，`git diff --exit-code` 就是現成的回歸測試。

## 第三課：解析出來的內容要真的讀一遍，官方檔案也會錯

解析成功不等於內容正確。逐題掃過去發現三處官方 PDF 本身的問題：

- **q004**：四個選項的位置印的是解析文字，選項本身不見了。翻到 PDF 第 22 頁確認是原始檔的誤植。
- **q078**：答案欄寫 `Ans（C）`，但它自己的解析全篇在論證選項 (A)。**答案與理由互相矛盾**。
- **q060**：解析只有一句「DoS 的定義。」，而題目問的是 SSL/TLS。

q078 這一題特別值得記住：它是**自己打自己**的錯誤。答案字母與解析文字放在同一份檔案裡，
只要讀一遍就會發現，但只要不讀、只做格式驗證，它就會安靜地進到題庫裡，
讓使用者背下一個錯的答案。

三處都修在**手寫層**（`explanations/*.ts`），不動機器產物，重跑解析不會被洗掉。
全部記進 `docs/coverage/bank-defects.md`。q004 的選項是 LLM 依解析內容反推還原的，
是全站唯一題幹文字非原文的題目，已單獨列管。

**教訓**：把「解析出 N 題、無空白選項」當成通過標準是不夠的。
**官方檔案也會錯，而且錯得很安靜。**

## 第四課：LLM 命題的失敗模式是可預測的，因此可以測

寫 500 題新題目時，第一版每一批都壞在同樣的地方：

| | 實測 |
|---|---|
| senior-ai-tech 答案分布 | A:69 / B:27 / C:4 / **D:0** |
| aiot-junior-basics 答案分布 | **A:86** |
| 考科二初版認知層級 | L1 7%（要求 10–15）、L4 28%（要求 20–25） |

A 佔七成的題庫，「不會就選 A」的期望值高過真的去讀。這不是內容問題，是**結構性失效**，
而結構性失效可以用測試擋。

擋下這些的是既有的 `tests/practiceBank.test.ts`——它在 2026-08-13 那批初級新題庫時就寫好了，
這次直接接住了三個新科目。**先前為了自己寫的守衛，在下一批資料進來時自動生效**，
這是這次最省事的一段。

但第一次修的時候修錯了方向：直接輪替 A、B、C、D，結果每四題恰好是一個 ABCD 排列——
比原本的偏斜**更好猜**。同一支測試的區塊檢查立刻擋下。

**教訓**：平衡不等於隨機。修正一種規律時，很容易製造出另一種更強的規律。

## 第五課：換位時要同步搬的東西有三樣，型別檢查一樣都抓不到

答案字母重新配置的做法是交換「正解選項」與「目標字母選項」的文字。題目語意不變，
但有三樣東西必須跟著搬：

1. `choiceExplanations` 的鍵
2. `meta.distractorTypes` 的鍵
3. **詳解裡「若把選項 C 改成⋯」這類指名字母的句型**（指的一律是正解）

第一輪只搬了第 1 樣，干擾類型全部標到錯的選項上。補上第 2 樣之後，
以為驗完了——因為當時的檢查是「鍵是否一致」，而三樣裡只有前兩樣是鍵。

第 3 樣是散文，藏在字串裡。實際壞了 **8 題**，其中 **3 題在早先已經宣告「驗證通過」的
`aiot-junior-basics` 裡**。

這件事的性質值得停下來看：**我當時的驗證方法定義了我能發現的缺陷種類。**
檢查鍵的一致性，就只會發現鍵的問題；散文裡的字母從來不在視野內，
所以「0 個不一致」這個結果是真的，但它回答的不是「這批題目對不對」，
而是「我檢查的那件事對不對」。這兩者的差距，正好是那 3 題。

現在 `tests/aiotQuestionBank.test.ts` 掃所有散文欄位，凡出現「選項 X」就斷言 X 等於正解。

**推論寫進了方針**：寫詳解時盡量不要指名字母。用「把它改成⋯」而不是「把選項 C 改成⋯」，
這類缺陷就從源頭消失。

## 第六課：憑印象寫節點名稱，寫掉了 16 題

考科二的 B2.2 我按印象寫成「物聯網軟體與韌體開發」，一路寫完 16 題韌體開發的題目。
實際的節點是「**雲端環境數據收集與平台設計**」。

`topic` 是個字串，型別檢查沒有意見。是後來跑 `grep` 對照 `assessmentTopics.ts` 才發現的。
16 題整組砍掉重寫。

那 16 題韌體題本身沒有問題——問題是**大綱裡沒有它們的位置**。這也是個提醒：
題庫的邊界由官方大綱決定，不由「這個主題值得考」決定。

**教訓**：寫之前先 grep 一次，把節點碼與名稱抄下來。三十秒的動作，這次省下的話是 16 題。

## 其他觀察

### 事件委派的選擇器清單是這個架構的稅

`main.ts` 用單一 `closest("[data-cert],[data-level],…")` 攔截所有點擊。這次新增了
五個可點擊屬性（`data-cert`、`data-study-jump`、`data-study-action`、`data-topic-drill`、
`data-study-read`），每一個都必須手動加進那串選擇器。

漏掉的症狀是「點了沒反應」——沒有錯誤訊息、沒有 console 警告，就是安靜地什麼都不發生。
`CLAUDE.md` 裡已經記著這個坑（前次因漏 `data-paper` 導致選卷無反應），這次照著做沒有再踩。

反過來也成立：**不想被點的元素就不要掛這些屬性**。題數為 0 的科目卡（AIoT 考科二在
自編題之前）刻意不掛 `data-subject`，因此不需要另外寫攔截邏輯。

### 「所有工具都套到五科」比想像中危險

學習主題頁的工具做完 AIoT 後推廣到五科，最容易寫錯的是**用選擇器直接抓某一張證照的區塊**。
一旦這麼寫，在 AIoT 上操作搜尋框會改到五科的區塊。

解法是所有處理函式一律用 `certSectionOf(element)` 從被點的控制項往上找
`[data-cert-section]`。這條規則已寫進 `CLAUDE.md`。

### 資料驅動的 UI 開關

「考前速記」按鈕依資料決定是否出現：該證照的筆記若沒有 formula／confuse 分節就不渲染。
五科的節名是「3.3 機器學習概念」這類、全歸 other，因此五科不顯示這顆按鈕。

如果無條件渲染，五科的使用者按下去會看到一整片空白，然後合理地認為是壞的。
**沒有內容時不要提供入口**，比提供了再顯示「查無資料」好。

### 用完即丟的腳本，該留下來的要留

字母重配、序列生成、字母引用修正這三件事當時是用 `/tmp` 裡的 Python 腳本做的。
寫這份回顧時才意識到：如果不留，方針文件只能寫「我用了一個已經不存在的腳本」。

已改寫為 `scripts/rebalance-answers.ts`（決定性亂數、預設 dry-run），
並以「跑在複本上 → 驗證全部不變式 → 刪除複本」確認移植無失真。

## 待辦

1. **內容查核。** 640 題全部是 LLM 產出或 LLM 校對，無人工事實查核。風險最高的是
   AIoT 考科二的 160 題（60 自編 ＋ 100 新題庫）——該科**沒有任何官方題源**。
2. **AIoT 的題數與配分**仍未查證（簡章只寫「每科 100 分、70 分及格」），
   因此兩科的 `mockExam` 為 `false`。拿到官方數字前不要打開模擬考。
3. **五科的新題庫沒有 `meta`。** 判斷分界只有 AIoT 兩科有。要補的話是 500 題的工作量，
   應先確認這個欄位對使用者真的有價值再投入。

## 一句話總結

**驗證方法決定了能發現的缺陷種類**——這次三個最真實的缺陷（q078 自相矛盾的官方答案、
散文裡指錯的選項字母、憑印象寫錯的節點名稱）都不在當時的檢查範圍內，
而它們全都只需要「真的讀一遍」或「grep 一次」就會現形。
