# 回顧：「最長的選項就是答案」——LLM 題庫的長度線索（2026-10-28）

起因：使用者在刷 AIoT 考科二新題庫時（`aiot-junior-iot-practice-q042`，B1.3），
發現正解「稽核日誌，記錄操作者、時間、對象與動作」是唯一一個帶說明的選項，
其餘三個都是光禿禿的名詞（傳輸加密／資料壓縮／負載平衡），不懂內容也選得出來；
而且「這一系列有好幾題都這樣」。

## 量測

**方法**：選項文字去空白後算字數。「正解最長」指正解嚴格長於三個干擾項。
「只挑最長」指一個完全不懂內容的考生每題都選最長的選項；遇到「何者不正確」的題目則反過來選最短的。
隨機猜的期望是 25 分。

| 題庫 | 題數 | 只挑最長得分 | 正解 ≥ 1.5× 最長干擾 |
|---|---:|---:|---:|
| **AIoT 考科二 新題庫（practice）** | 160 | **83** | 29% |
| AIoT 考科二 自編（generated） | 60 | 73 | 45% |
| AIoT 考科一 新題庫 | 190 | 61 | 13% |
| 中級 senior-ml 新題庫 | 142 | **97** | 85% |
| 中級 senior-bigdata 新題庫 | 166 | 89 | 75% |
| 中級 senior-ai-tech 新題庫 | 142 | 87 | 73% |
| 初級 junior-ai-basics 新題庫 | 145 | 48 | 30% |
| 初級 junior-genai 新題庫 | 120 | 38 | 17% |
| 五科 `generated/*`（舊的 gen 題） | 24–34／科 | 71–88 | 17–65% |
| *官方：AIoT 學習指引練習評量* | 80 | *36* | 16% |
| *官方：初級真題* | 229–240 | *44–45* | 3–4% |
| *官方：中級真題* | 130–140 | *46–63* | 12–22% |

**結論：AIoT 考科二新題庫只靠「挑最長」就能拿 83 分，超過 70 分及格線**；中級三科的新題庫
更嚴重（87–97 分）。官方題目也有長度偏差（36–63 分），但從來沒有到「不讀題也能及格」的程度。
換句話說，這不是 iPAS 的出題風格，而是 LLM 命題的系統性破綻。

刷這些題庫拿到的高分**會高估實力**：一部分分數來自應試技巧，不是來自懂內容。

## 樣貌：三種造成長度差的寫法（以考科二新題庫 160 題為例）

正解最長的有 127 題。

1. **正解附補述，干擾項只有名詞**（63 題，約一半）。正解為了「毫無爭議地對」被補上定義或理由，
   干擾項卻沒有。截圖那題就是這樣。
2. **正解是多項並列的完整答案，干擾項各只講一項**（18 題）。例：縱深防禦題的正解是
   「裝置端做安全開機與韌體簽章、網路做 TLS 與網段隔離、平台做最小權限與稽核」，
   干擾項則是「只靠雲端防火牆」「密碼統一設成同一組」。
3. **判斷題（L4）的正解帶條件，干擾項是一刀切的極端**。依認知層級拆開看，L4 題正解最長的比例高達
   **95%**（L1–L3 為 71–78%）。權衡題的正確答案天生就是「先…再…，並且…」，
   錯誤答案則是「直接…」「只要…」。這一型最難修，也最容易洩題。

「干擾項含絕對語（只要、所有、不需要、直接取代⋯）」是另一條常見線索，但官方真題也有同樣的分布，
疊加在長度線索上也沒有多拿到分數，所以不列為本次的主要問題。

另外，第二批（`*.2026.ts`）的「正解 ≥ 1.5× 最長干擾」降到 0%，但正解最長的比例反而升到 85%：
極端的長度差被修掉了，正解卻仍然**每題都多幾個字**。所以只看極端值的檢查擋不住這個問題，
要看整體比例。

## 為什麼一直沒被發現

- **規則早就寫了，但從來沒有被量測。** 2026-08-13 的新題庫 spec 與 plan、以及
  `docs/question-authoring.md` §2.7，都明文寫了「四個選項長度相近；正解特別長或特別具體是最好認的破綻」。
  可是測試只檢查了**容易量的**分布：正解字母比例、認知層級、題型、跨節點。
  長度同樣容易量，卻沒有人把它寫成測試。
- **內容複審看的是「對不對」，不是「好不好猜」。** 初級新題庫經過八輪 LLM 內容複審，
  每一輪都在確認正解是否正確、詳解是否吻合，沒有一輪站在「不懂內容的考生」的角度看選項。
  逐題閱讀時，「正解寫得比較完整」看起來是優點，不像缺陷。這個問題只有把整個題庫放在一起統計才看得出來。
- 這和 2026-08-17 回顧的教訓同構：**寫在文件裡、沒有變成測試的規則，等於沒有規則**。

## 該做的事

1. **加守衛測試**（`tests/choiceLength.test.ts`）：每個 LLM 題庫的「只挑最長得分」不得高於
   同證照官方題目的基準 ＋ 10 分。實際門檻約為：初級與 AIoT 不高於 50 分，中級不高於 65 分。
   另外，單題的正解不得達到最長干擾項的 1.5 倍以上（短選項的計算題用絕對差豁免）。
   現況會讓多個題庫不及格，所以先用棘輪（只准變好）的方式上線，再逐科收緊。
2. **改寫選項**，優先順序依「離考試多近 × 洩題多嚴重」：
   AIoT 考科二（160 ＋ 60）→ AIoT 考科一 → 中級三科 → 初級兩科。
   - 手法以**加長干擾項**為主：替每個錯誤選項補上一個「聽起來合理但錯」的理由，
     而不是刪短正解。這樣正解文字、詳解與 `choiceExplanations` 都不必動，只需確認補上的理由
     與該選項的錯誤選項解析一致。
   - L4 判斷題則讓干擾項**也帶條件**（條件寫錯，或順序顛倒），不要只放一刀切的極端選項。
   - 改完要重跑 `tests/questionBankMeta.test.ts`。`distractorTypes` 的分類可能因此改變，
     例如原本的「Absolute Statement」補上理由後，可能變成「Wrong Condition」。
3. **在 `docs/question-authoring.md` §2.7 把「長度相近」改成可驗收的數字**，並附上本文的量測腳本。

## 修正結果：AIoT 考科二 220 題（2026-10-28）

做法：把三個檔案匯出成 JSON，交給四個子代理平行改寫。子代理**只產出修改內容（新的選項文字、解析與干擾類型），不直接動原始碼**，
由套用腳本以「題目 id 區塊內精確比對」的方式寫回，再重新載入資料逐欄比對（701 處，0 處不一致）。
每個子代理都拿同一支檢查腳本自我驗收：正解嚴格最長 ≤30%、最短 ≤35%、正解 ≥1.3× 最長干擾為 0。

| 題庫 | 只挑最長（前 → 後） | 正解最長比例（前 → 後） | 正解 ≥1.5× 最長干擾 |
|---|---:|---:|---:|
| 考科二 新題庫 160 題 | 83 → **23** | 79% → 16% | 29% → 0% |
| 考科二 自編 60 題 | 73 → **33** | 73% → 22% | 45% → 0% |

- 改了 167 題，主要做法是**加長干擾項**；約 40 題同步改寫了選項解析，8 處干擾類型跟著改。
  正解精簡了 40 題，都只刪贅字，並確認詳解沒有逐字引用被刪掉的部分。
- 過程中發現的反向風險：某一批第一版把「正解最長」壓到只剩 3%，變成「正解從來不是最長」的反向線索，
  於是還原了幾題差距只有 1–3 字的改動。**目標是讓長度名次隨機，不是讓正解變短。**
- 子代理點名的約 20 題「干擾項變強、需要再看一眼」的題目已由主流程逐題檢視。只有 gen-q035 A 的選項解析
  沒有回應新加的理由，已補寫。其餘都判斷仍有唯一正解，但這批題目**同樣未經人工事實查核**。
- 守衛測試 `tests/choiceLength.test.ts` 已上線：考科二兩個題庫適用目標門檻，其他 11 個 LLM 題庫以現況為上限（棘輪）。
