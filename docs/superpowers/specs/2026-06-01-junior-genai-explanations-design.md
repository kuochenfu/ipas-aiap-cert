## 複審工作表規格

`docs/superpowers/review/junior-genai-review.md`，欄位：

`id` ｜ `年次題號(sourceRef)` ｜ `答案` ｜ `L章節` ｜ `信心` ｜ `依據(一句)` ｜ `詳解全文` ｜ `狀態`

- **詳解全文**欄與 `.ts` map 是**同一份文字**（同一次產生）。複審改工作表 → 同步回 `.ts`，避免雙份漂移。
- 表格依 `信心 低→中→高` 排序。
- `狀態` 預設「待複審」，複審後改「已確認」或「需改」。

### 信心度 rubric

- **高** — 官方答案明確、詳解直接對應學習指引、選項對錯清楚。
- **中** — 答案合理但詳解涉及一定推論或外部知識，建議複審。
- **低** — 題目模糊／需較多假設／選項文字不全／不確定 → **優先人工複審**。

## 產生方法

- 每題詳解任務：解釋官方既定答案為何正確、其他選項為何錯，**錨定到對應 L 章節概念**，不引入無法驗證的外部事實。
- 單次起草 + 自我標註信心度；**人工複審（工作表）為品質關卡**。低信心題自動置頂。
- 邊界：若真題選項文字不全或題意模糊，標**低信心**並在「依據」註明，不硬掰。
- 新題依官方學習指引撰寫，附正解與詳解，`source: "generated"`、帶正確 `topic`/`difficulty`，亦列入工作表複審。

## 樣本（供確認格式與文風）

### 樣本詳解 A — L123 風險/偏差（115年第一次 第1題，答案 A，信心 高）

> 題目要在「模型架構與推論設定皆未調整」前提下優先降低偏差風險。模型偏差多源於訓練資料的代表性不足，故應先重新檢視訓練資料的樣本分布與代表性（A）。限制只顯示高銷量商品（B）會加劇熱門偏差；縮小參數（C）與提高隨機性（D）皆未觸及偏差根源，反可能損害推薦品質。

依據：偏差治理優先檢視資料代表性（L123 風險管理）。

### 樣本詳解 B — L121 Low Code 模型概念（114年第四梯次 第1題，答案 B，信心 高）

> 在 Low Code 平台中，「模型（Model）」是用來抽象描述資料結構、業務流程與介面邏輯的核心元素，直接影響應用的設計與後續維護（B）。它不只是視覺輔助（A），也不受限於傳統 UML、缺乏延展性（C），更未被自動產碼全面取代（D）——自動產碼正是以模型為輸入。

依據：Low Code 的 Model 為描述資料/流程/介面的核心抽象（L121 概念）。

### 樣本詳解 C — L123 隱私保護導入（114年第四梯次 第2題，答案 D，信心 中）

> 需求是跨部門/機構運用大量敏感文本、在保護隱私下持續優化模型並降低外洩風險，最適合的是聯邦學習（Federated Learning，D）：資料留在各端、只交換模型更新。同態加密（A）、安全多方計算（B）、零知識證明（C）皆為隱私技術，但非「讓模型在分散資料上持續訓練」的整體框架，故 D 最貼合情境。

依據：聯邦學習＝資料不出本地的協作訓練（L123 導入/資料安全）；標中信心因 A/B/C 亦屬隱私技術，需確認題意取整體框架。
